# 桌面资料工作台：设计取舍

日期：2026-10-28。对应源码版本：0.3.0-rc.1。本文记录产品设计依据；真实窗口与运行时结果见[改革报告](../reports/2026-10-28-desktop-product-reform.md)。

## 目标不是再做一套文献管理器

本产品已经有集合、保存筛选、阅读进度、批量操作、MCP 和任务中心。此次改造不重复造这些功能，也不增加外部账户、收费服务、全文向量库或新的数据搬运规则。重点是让已有能力在真实阅读过程中更容易发现、少绕路、出错后能继续。

改革前对已运行桌面版的检查发现：标题搜索的结果被表单挤到首屏下方；同时有本地文件的 PDF 直接走远程 URL 并加载失败；收藏列表会展示详情禁止访问的系统隐藏集合；错误统一提示恢复 API，掩盖了“记录不存在”的真实类别。代码审计还发现独立网站/容器与桌面维护两套生命周期。

## 阅读流程

1. 在“全部资料”或保存视图确定范围；关键词、会议、发表年份和首次公开日期保持各自语义。
2. 用列表扫题名、会议/年份、阅读状态与材料可用性；需要完整摘要时展开详细卡片。
3. 打开原文时先经过 API 的受控打开动作：有本地 `path_ref` 时不由前端擅自改走外部 URL。
4. 多版本明确标注；续读以表示 ID、来源指纹和页码共同决定，恢复过程不自动写回第一页。
5. 出错时对症恢复：重新取安全会话、重试文件、重新加载最新版本或返回列表。不存在的记录不建议重启数据库。

“代码 URL”“已下载的源码”和“可以复现实验”仍然是不同事实。引用、代码、材料状态与候选/缺失限制继续保留。

## 桌面边界

- 静态前端内嵌 Tauri；不再有独立 Web host、Vite devUrl、预览站点或云端 Web 模板。
- `apps/web` 只是沿用的源码目录名。删除网站产品不等于删除 React 组件，也不等于取消 MCP 所需的 API。
- API 与安全网关保持不同端口与 Origin；来源签名、CSP、CSRF 不能为了“只剩一个端口”而取消。
- 生产缺运行时应明确失败，不能猜源码或系统 Python。开发显式声明 source/runtime/data-dir，进入同一监督器。
- 启动不得通过扫描模块名杀占用者，也不得仅凭一个端口接受连接就认领陌生数据库。

## 确认删除与保留

已退役的独立网站、云部署模板、重复脚本监督器和无调用的 graph/score-boost 代码不留兼容空壳。旧浏览器产品 fixture 的有用加载页断言迁移到 JSDOM；真实交互由原生窗口验收，而不是把普通浏览器测试当桌面验收。

关键词 RRF 融合仍有实际调用，保留；持久化历史枚举和数据库迁移不因名字含 vector/RAG 而改写。Playwright/axe 仍为论文 HTML 审计所用，不因退役产品网站误删。这些保留项有具体调用者，不是“万一以后用到”的备用实现。
